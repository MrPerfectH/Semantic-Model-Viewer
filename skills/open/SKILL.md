---
name: open
description: Opens a Power BI semantic model in the actual interactive Semantic Model Viewer. Use when asked to open or visually explore a TMDL or BIM model, its tables, or a measure.
argument-hint: "[model path] [table or measure to focus]"
disable-model-invocation: true
---

Open the model requested in $ARGUMENTS using the existing viewer, with the narrowest useful initial focus.

1. Treat arguments as user input, never as shell syntax. If no model path was provided, run `node "${CLAUDE_PLUGIN_ROOT}/bin/smv.cjs" discover .` from the user's project. Use the only discovered model, or ask the user to choose if several match. Do not silently use the plugin's demo. Inputs are TMDL model folders, their definition folders, or BIM files; PBIX is unsupported.
2. Use this plugin's `smv_inspect` MCP tool on the selected model to obtain exact table names, qualified measures, relationship identifiers and formulas. Read its provenance: show the exact local source path and state that this is local metadata, not the published Power BI model. If it warns about a backup path, confirm that source before relying on it. Never silently pick a backup folder. The server is `plugin:semantic-model-viewer:viewer`; tool names may be prefixed by the host. `smv_sessions` shows `SMV_ROOT` and existing sessions; reuse a matching session for follow-up work instead of opening duplicates.
3. Call `smv_open` with the model path and a version 2 view. For tables, use `{"version":2,"mode":"graph","tables":["Sales","Date"]}` with actual names. For a measure, use `{"version":2,"mode":"measures","focus":{"kind":"measure","table":"Measures","name":"Total Sales"},"context":{"direction":"up","depth":1,"limit":25}}` with its inspected home table and name. Without a requested focus, use a graph view of the inspected tables. Do not invent annotations or diagnoses.
4. Treat `presentation.preferred` as a routing hint. `inline.available` and `inline.advertised` mean the host advertised MCP Apps, not that chat displayed a view. Try the provided app once when advertised and appropriate to the user's request; never claim it appeared without evidence. If no inline view appears, state that limitation and offer the same session URL or export, rather than repeatedly calling `smv_open`. A browser pane or file side panel is a separate presentation route and must not be described as inline chat. A reachable browser can be used even before the server has observed its acknowledgement. Check `smv_status` for updated route observations. Opening the MCP session starts a local server, not the system browser.
5. Retain the returned session ID and revision for follow-up questions. Read `smv_selection` for “this one”; use a client ID when multiple tabs are active. Before `smv_update`, read `smv_status` and pass the current revision. An update is requested until the viewer acknowledges it; respect Apply/Keep exploring.

If MCP is unavailable, read `${CLAUDE_PLUGIN_ROOT}/docs/interactive-viewer.md` and use the CLI fallback with the absolute plugin CLI path and a session file under the user's project. Report the MCP error. Do not configure a second MCP server automatically. Stop temporary CLI sessions explicitly; MCP sessions stop when their connection closes. Keep a live session available while the user is exploring it.

For portable output, use `smv_export` with `out` omitted to create a gitignored file under `.smv-artifacts`; its receipt supplies path, bytes and SHA-256. Use host-native file attachments or links without dumping megabytes of HTML into context. Respect any host rule requiring inspection before publication; if that cannot be satisfied, explain the limit and provide an allowed local file/browser link. Do not claim that an artifact was published inline. Read `${CLAUDE_PLUGIN_ROOT}/docs/mcp-usage.md` for examples. Stop extra temporary sessions using `smv_stop`, retaining a session the user is actively exploring. Models are read without executing DAX, SQL or M. Parsed metadata supplied to Claude follows the configured provider's data handling.
