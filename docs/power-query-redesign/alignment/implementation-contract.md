## Final shell contents

Library: Power Query / N objects in this model / M on canvas; search; All objects / On canvas / Available; one connectivity facet All / Connected / Disconnected with full-registry counts; compact rows with name, kind/table/partition subtitle and +/−. A disconnected category still says “Zero resolved incident references; static uncertainty remains.”

Toolbar: Query canvas + visible/total count; Back; Blank layout; Show all; Undo; Arrange; Display. PQ-only Back is visually the same button as Tables Undo. Keep the Queries collapse toggle reachable at narrow widths; do not hide the library without a visible way back. Display contains existing supported canvas display options, overview visibility, reference legend and global static-analysis details. Do not offer unrelated Tables role rules or unsupported layout algorithms. The visual mock demonstrates a subset; the production Display must expose only real capabilities.

Save view/Saved views are omitted in this scoped pass: existing save handlers serialize Tables state and cannot be wired honestly to PQ without a new persistence contract. This does not remove those controls from Tables. PQ arrangement survives perspective roundtrips in the current immutable model via existing suspend/layout state. Do not expand export/persistence scope to copy M or presentation context. If future persistent PQ views are requested, handle them as separate explicitly versioned source-free layout records.

Initial PQ ready state remains the whole-model overview (all objects, including disconnected/status nodes), not Tables' empty-first workspace. No arbitrary limit, “expand to discover,” default connected-only gate or hidden parameter fanout. Selection opens the inspector; use Fit for the entire current visible projection and Center selected for readable focus.

## Selection, membership, visibility and history contract

Definitions: R = complete graph registry; M = canvas membership (initially R); C = complete-registry connectivity category; F = selected object's graph neighborhood; S = search matches. Build F from supplied inputId→consumerId edges, using graph IDs with a visited set, so cycles are bounded. Inputs traverse consumer→input; consumers traverse input→consumer; connected traverses either direction. Always include selected in F. Depth 0 is Selected only; 1 direct; 2 two; infinity all. This traversal must not parse M or invent relationships.

Rendered nodes V = M ∩ C ∩ (Hide unrelated and selected ? F : R). Search filters library results and dims nonmatches; it does not change V, category counts or registry membership. In Dim unrelated mode, non-F nodes/edges are subdued using existing Tables opacity language; search dimming combines with focus dimming rather than replacing it. Render an edge only when both endpoints are in V. Keep selected ring/focus distinguishable even if category hides its card; inspector stays until explicit close/removal/reset.

| Action | State and visible result |
|---|---|

| Click card or Enter | Select one and inspect; other cards remain members. Dim unrelated is default; hide mode follows selected if active. Ordinary background click clears selection and closes inspector; drag does not. |

Do not relabel the known PQ-specific differences as “identical behavior.” Whole-model initial state, readable-target Show all, Back/close semantics, complete minimap and safe M inspection are the intentional exceptions to the shared Tables presentation.

## Artifact limits

The interactive visual is intentionally an authored demonstration. It uses synthetic captured context and current canvas/inspector code with temporary geometry/styles plus a small UI adapter. Header navigation is visual context; only demonstrator controls act. It is fixed at 1280×800 and scales in the report; it does not prove responsive docking, true zoom, production history correctness, worker cancellation, scale, packaging or native behavior. Some advanced production controls (drag-add, contextual table partition choice, full Display, Add/Remove related) are specified here but not implemented in the visual. Exact original-M handling in production remains governed by the existing renderer/contract, not by prototype success.
