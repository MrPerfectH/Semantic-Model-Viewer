# Selection, explicit framing, and M panel placement (r9)

User feedback on 2026-10-10 supersedes automatic readable reveal for ordinary card/library selection in the older alignment contract. Follow input/consumer, source-reference links, Inspect target, Trace, Hide, Arrange and Show all retain deliberate navigation/framing behavior. Ordinary inspection keeps exact numeric viewport (x/y/k), node coordinates and the existing body scroll; neither inspector docking nor ResizeObserver may translate the canvas. Hidden/new library membership still uses the existing metadata identity, placement and filter rules. Flow target remains stable. Explicit **Frame related flow** applies the current target/direction/depth projection and frames it; Back restores the prior navigation state.

**Center selected** centers a visible selected card in the browser-visible canvas rectangle, excluding toolbar and available navigation/map space. At bottom docking it first exposes the canvas scroll region. It is synchronous and repeatable, does not change node coordinates/root, and never runs as a delayed selection effect. Hidden selections remain disabled. Fit overview keeps the honest complete projection; readable long-flow fallback is retained on deliberate framing.

Display → **M query panel** offers Right and Bottom. Right automatically falls below when the remaining canvas would be too narrow; the preference itself stays Right and returns on widening. Bottom remains Bottom. Only `{dock,width,height}` is persisted in `smv.pq.inspector.v1`; it contains no model/query identity or source. Sizes are bounded 300–650 CSS px, independently retained for side/bottom. Separator uses orientation-specific arrow keys, Home/End, pointer capture and live ARIA value/orientation/text. Model changes and perspective transitions preserve this presentation preference. Back/Undo preserve their existing model/navigation and inspector state without rewriting a subsequently chosen global docking preference. The exact same code card is moved to/from the expanded reader; source, copy and UTF16 ranges are unchanged.

The analyzer has an additive `standardLibrary` name list on analyzed results. It classifies only explicit exact, case-sensitive documented identifiers, **after local bindings and exact model-name/identity resolution**. No regex or namespace-prefix inference is allowed. Model collisions resolve as before; duplicate names/identities stay ambiguous; unknown names, dynamic access and incomplete parses remain uncertainty. Recognized names never create model edges or establish execution. The graph forwards the list as an informational `standard-library` issue and continues forwarding analyzer uncertainty strings opaquely. The generic final notice remains last in `uncertainty` by the existing analyzer contract.

The initial bounded catalog covers Table.TransformColumnTypes and the documented numeric/Guid type names. References: [Table.TransformColumnTypes](https://learn.microsoft.com/en-us/powerquery-m/table-transformcolumntypes) and [Types and type conversion](https://learn.microsoft.com/en-us/powerquery-m/type-conversion), checked 2026-10-10. The catalog is intentionally incomplete; an unrecognized dotted name remains visible as unconfirmed rather than silently treated as a library function. The UI explains that reading M text without running it can miss links and does not establish that a query is broken.

Straight orthogonal paths and open chevrons remain the current reviewed connector contract; reciprocal directed hit routing is unchanged. Older curved-arrow screenshots cannot be attributed to this runtime without their loaded URL/asset hashes. No source model, M execution, connector fetch, snapshot export schema or native lifecycle changes are authorized by this contract.
